# Dumber

Re-explain the last thing as if to someone with zero background in this domain — no prior programming knowledge assumed unless the topic genuinely requires it.

- Drop all jargon. If a technical term is unavoidable, define it in one plain-language clause right where it's used.
- Use a real-world analogy if one actually fits — don't force one that doesn't.
- One idea per sentence. Short sentences.
- Skip the "why this matters" framing and the caveats — just the plainest possible version of what's actually going on.
- If the original explanation had multiple parts, simplify each part separately rather than compressing them into one dense paragraph.
- It's fine for this to be longer than a normal terse reply — clarity wins over brevity here.

Don't just repeat the same explanation shorter. Actually rebuild it from the ground up assuming no context.
